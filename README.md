# HydroESP-C3

Локальный контроллер полива/гидропонной установки на **ESP32-C3 Super Mini**. Управляет насосом по расписанию или вручную, хранит настройки в NVS, синхронизирует время по NTP и предоставляет OLED, Serial и адаптивный веб-интерфейс.

> Важно: базовый режим проекта — **таймерное управление**, а не универсальная модель потребности растений в воде. Научно корректный адаптивный режим требует датчиков и калибровки конкретной установки. Подробности — в [`AUDIT.md`](AUDIT.md).

## Возможности

- безопасный по времени ручной запуск насоса;
- суточное расписание до 48 циклов;
- сохранение расписания, Wi‑Fi и часового пояса в NVS;
- NTP и mDNS (`hydro.local`);
- OLED 72×40;
- локальный веб-интерфейс без CDN и облака;
- OTA-обновление `.bin`;
- fallback в режим точки доступа при отсутствии Wi‑Fi;
- PlatformIO build CI.

## Веб-интерфейс

Интерфейс имеет отдельные компоновки для desktop и mobile:

- **Обзор** — состояние устройства, Wi‑Fi, IP, uptime, следующий цикл, ручное управление насосом и обратный отсчёт;
- **Расписание** — добавление/удаление до 48 циклов, валидация дублей и длительности, расчёт суммарного времени насоса;
- **Расчёт** — гидравлический расчёт длительности цикла по фактическому расходу и эффективной подаче, оценка VPD и генерация редактируемого графика;
- **Настройки** — Wi‑Fi и UTC offset; сохранённый пароль не выгружается обратно в браузер;
- **Прошивка** — drag-and-drop OTA с прогрессом.

Нативные браузерные `alert()`/`confirm()` не используются: уведомления отображаются toast-компонентами, подтверждения — неблокирующим modal-dialog.

## Инженерный расчёт

Встроенный калькулятор использует измеряемый водный баланс:

```text
V_event = N × d / 1000

t_on = 60 × V_event / (Q × η)
```

где `N` — количество растений, `d` — подача на растение за цикл (мл), `Q` — фактический расход системы (л/мин), `η` — коэффициент эффективной доставки, `t_on` — длительность работы насоса.

VPD рассчитывается как диагностический показатель по температуре и RH, но не изменяет полив автоматически. Для адаптивного управления нужны как минимум микроклимат, свет/радиация и обратная связь по воде/корневой зоне. Предлагаемая архитектура приведена в [`AUDIT.md`](AUDIT.md).

## Исходное расписание

Заводской пресет в `src/config.h` предназначен для текущей экспериментальной конфигурации с минеральной ватой:

- старт: 06:00;
- основной дневной участок: интервалы 20–30 минут в зависимости от времени суток;
- завершение: 19:00;
- длительность отдельных циклов: 120–180 секунд.

Это **не универсальная рекомендация** для аэропоники или любой культуры. Перед эксплуатацией график нужно сопоставить с производительностью насоса, количеством растений, субстратом, освещением, микроклиматом и фактическим возвратом/дренажом.

## Сборка

Требуется PlatformIO.

```bash
export WIFI_SSID="My_WiFi"
export WIFI_PASSWORD="My_Password"
pio run
pio run --target upload
```

Монитор порта:

```bash
pio device monitor
```

## Подключение ESP32-C3 Super Mini

| Компонент | GPIO | Примечание |
|---|---:|---|
| Relay IN | 4 | `OUTPUT_OPEN_DRAIN` |
| OLED SDA | 5 | I²C |
| OLED SCL | 6 | I²C |
| LED | 8 | встроенный индикатор |
| BOOT | 9 | кнопка |

## Эксплуатационные ограничения

До применения в недоверенной сети необходимо закрыть два пункта:

1. OTA сейчас не имеет аутентификации/проверки подписи образа.
2. provisioning AP `HydroESP-Setup` по умолчанию открыт.

Также текущая версия отключает brown-out detector. Это следует считать временным аппаратным workaround: для надёжной эксплуатации предпочтительно устранить просадку питания насоса и вернуть штатную защиту ESP32-C3.

Полный аудит, приоритеты и план сенсорного адаптивного управления: [`AUDIT.md`](AUDIT.md).
