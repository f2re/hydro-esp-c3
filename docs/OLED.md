# OLED: экраны и статусы

OLED у HydroESP-C3 — это аварийный локальный интерфейс, а не копия Web UI. Логическая видимая область текущего модуля — 72×40 пикселей, поэтому на экран выводятся только состояния, которые помогают понять, что контроллер делает прямо сейчас.

## Язык

Пользовательские состояния выводятся по-русски встроенным UTF-8/Cyrillic-шрифтом U8g2. Технические обозначения не переводятся:

- `IP` — сетевой адрес;
- `Wi-Fi` — имя технологии;
- `NTP` — синхронизация времени;
- `hydro.local` — имя устройства в сети;
- SSID показывается буквально, как задан в роутере.

Такой подход сохраняет понятность экрана и одновременно позволяет сопоставлять его с роутером, терминалом и документацией.

## Экраны нормальной работы

### Часы

Крупно показывается локальное время. В нижней строке — состояние Wi-Fi и хвост IPv4-адреса. Если время ещё не синхронизировано, появляется `NTP!`.

### Сайт

Экран **САЙТ** показывает полный IPv4 и `hydro.local`. При проблемах с Web UI именно этот IPv4 следует использовать для `curl`, браузера и `wifi-flash.sh`.

### Следующий запуск

Экран **СЛЕД.** показывает время следующего запуска, оставшееся время и длительность цикла.

Особые состояния имеют приоритет над обычным временем:

- **АВТОПОЛИВ / ПАУЗА** — автоматика отключена; сохранённые слоты не считаются активным обещанием запуска;
- **НЕТ NTP** — часы не синхронизированы, плановый запуск небезопасен;
- **НЕТ ПЛАНА** — расписание пустое.

### План

Экран **ПЛАН** показывает число слотов и ближайшие строки расписания. Текущий ближайший слот выделяется только когда NTP синхронизирован и автоматика включена.

### Полив

Во время включённого насоса обычная ротация экранов прекращается. Показываются **ПОЛИВ**, оставшиеся секунды и прогресс текущего запуска.

## Настройка Wi-Fi

В режиме `HydroESP-Setup` показываются:

- **НАСТРОЙКА**;
- SSID точки доступа;
- `IP 192.168.4.1`;
- значок открытого замка: setup-сеть без пароля.

## OTA

После начала любой прошивки OLED полностью передаётся OTA-контексту. Обычные страницы, scheduler и кнопка ручного старта не должны перерисовывать экран поверх процесса обновления.

Состояния:

- **ПРОШИВКА** + 0…99% — данные записываются;
- **ГОТОВО / 100%** — `Update.end(true)` завершён, ожидается контролируемая перезагрузка;
- **ОШИБКА / ПОВТОРИТЕ** — запись не завершилась успешно, автоматического reboot нет.

100% никогда не выводится по одному только количеству принятых HTTP-байт: multipart-запрос содержит служебные данные. 100% зарезервировано за успешным завершением `Update.end(true)`.

OLED не перерисовывается на каждый сетевой chunk. Обновление процентов ограничено видимым изменением и временным интервалом, чтобы не нагружать I²C и не создавать мерцание.

## Что намеренно не показывается

На 72×40 нет смысла постоянно выводить RSSI в подробностях, номер API, commit SHA, объём heap или длинные диагностические сообщения. Эти данные доступны в Web UI, `/api/diagnostics` и Serial. OLED должен отвечать на четыре вопроса:

1. устройство живо?
2. где его открыть?
3. что оно сейчас делает?
4. безопасна ли автоматика / прошивка?
