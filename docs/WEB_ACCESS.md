# Если Web UI не открывается

Сначала посмотрите на OLED — контроллер всегда старается показать адрес сайта.

## Новая или ненастроенная плата

Должно быть:

```text
SETUP WIFI
HydroESP-Setup
NO PASSWORD
OPEN 192.168.4.1
```

Подключитесь к **открытой** сети `HydroESP-Setup` и откройте:

```text
http://192.168.4.1
```

Сообщение телефона «без доступа к Интернету» нормально: эта сеть нужна только для локальной настройки контроллера.

## Ранее настроенная плата

`install` не удаляет старый Wi‑Fi. Контроллер подключится к сохранённой сети, а OLED периодически покажет страницу `WEB ADDRESS` с полным IPv4, например:

```text
192.168.1.57
```

Открывайте:

```text
http://192.168.1.57
```

`http://hydro.local` — удобный дополнительный адрес, но он зависит от mDNS роутера/клиента. Если не работает — используйте IP с OLED.

## Быстрая проверка сети и HTTP

```bash
curl http://192.168.1.57/ping
```

Ожидается:

```text
pong
```

Дополнительно:

```bash
curl -sS http://192.168.1.57/api/status
```

Если `/ping` и `/api/status` отвечают, Wi‑Fi, TCP и HTTP-сервер контроллера живы. Тогда проблема находится выше — в выдаче или выполнении Web UI, а не в подключении к сети.

Serial также печатает прямой адрес:

```bash
python3 tools/hydroctl.py monitor
```

Ищите:

```text
[WEB] Open: http://.../
```

## Если приходит `200 OK`, но страница белая

Проверьте заголовки и размер тела:

```bash
curl -sS -D /tmp/hydro-headers.txt \
  http://192.168.1.57/ \
  -o /tmp/hydro.html
cat /tmp/hydro-headers.txt
wc -c /tmp/hydro.html
```

Нормальная прошивка должна возвращать ненулевой HTML. Если видно `200 OK`, `content-type: text/html`, но `content-length: 0` и файл имеет 0 байт, это не проблема браузера: контроллер не отдал тело страницы.

В актуальной прошивке большой `WEB_UI_HTML` передаётся напрямую из `PROGMEM` через explicit-length `AsyncProgmemResponse`; целиком в Arduino `String` он больше не копируется.

Такую старую/повреждённую прошивку можно обновить **без работающей главной страницы**:

```bash
./wifi-flash.sh 192.168.1.57
```

Команда сначала использует независимый recovery OTA `3232`, а для более старой прошивки автоматически пробует прямой HTTP `/ota/upload`.

## Проверка favicon

Актуальная прошивка должна отвечать на оба ресурса:

```bash
curl -I http://192.168.1.57/favicon.ico
curl -I http://192.168.1.57/favicon.svg
```

Ожидаются `200 OK` и типы `image/x-icon` / `image/svg+xml`. Если `/favicon.ico` даёт `404`, контроллер работает на версии до встроенного favicon.

Иконка кэшируется браузером до семи суток. После обновления её иногда нужно обновить hard reload'ом или закрыть и открыть вкладку заново.

## Если `HydroESP-Setup` нет

Это не обязательно ошибка. Если плата уже была настроена раньше, она использует сохранённую домашнюю сеть. Смотрите IP на OLED или в Serial.

Если плата новая и setup-сети нет, откройте Serial monitor и проверьте строки `[WiFi]`, `[SETUP]` и `[WEB]`.

## Если Web UI не работает, но устройство в сети

Не переходите сразу к USB. Используйте числовой IP с OLED:

```bash
./wifi-flash.sh 192.168.1.57
```

Recovery-канал специально сделан независимым от HTML/JavaScript панели.

## Если плата вообще не загружается

Не используйте standalone application `firmware.bin` как полный образ flash. Для обычной установки используйте `install.sh` / `install.ps1`; они сами прошивают bootloader, partitions и приложение в правильные области.

Если в Serial нет строки `[HydroESP]`, проблема ниже Web UI: USB, питание, bootloader/flash или reset loop.
