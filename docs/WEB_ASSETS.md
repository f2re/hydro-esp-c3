# Web-ресурсы и favicon HydroESP-C3

## Зачем отдельная схема

ESP32-C3 не должен расходовать heap на декоративные файлы. Поэтому favicon и другие статические Web-ресурсы HydroESP-C3 рассматриваются как часть прошивки, а не как файлы, которые надо копировать в NVS/LittleFS или собирать в большой `String` при каждом HTTP-запросе.

## Favicon

Фирменный знак — тёмный скруглённый квадрат, зелёная капля и белый росток. На 16×16 он остаётся различимым и не содержит текста или мелких декоративных деталей.

В прошивке есть два представления:

| Ресурс | Назначение | Размер |
|---|---|---:|
| `HYDRO_FAVICON_SVG` | масштабируемый исходник/современные клиенты | ~422 B |
| `HYDRO_FAVICON_ICO` | обычный browser favicon 16×16 + 32×32 | ~2262 B |
| **Итого** | payload в flash | **~2684 B** |

CI запрещает суммарному payload превышать 4096 B без явного пересмотра архитектуры.

## HTTP-маршруты

Контроллер отдаёт:

```text
GET /favicon.ico  -> image/x-icon
GET /favicon.svg  -> image/svg+xml
```

`/favicon.ico` нужен намеренно: Firefox, Chromium и другие браузеры часто запрашивают этот путь автоматически даже без отдельного `<link rel="icon">`. Поэтому favicon работает и для старого self-contained HTML, а в консоли больше нет штатного 404 на `/favicon.ico`.

Оба ответа получают:

```text
Cache-Control: public, max-age=604800
```

То есть браузер может держать иконку до семи суток и не запрашивать её при каждом открытии панели. После изменения самой иконки браузеру иногда нужен hard reload/очистка favicon cache.

## Память ESP32-C3

И SVG, и ICO объявлены `PROGMEM` в `src/web_assets.h` и находятся во flash вместе с application image.

Не используются:

- NVS;
- LittleFS/SPIFFS;
- отдельный partition для картинок;
- постоянный heap-буфер;
- Base64/data URI внутри большого Web UI.

Ответ создаётся через explicit-length `beginResponse(..., const uint8_t*, size)`. Для `ESPAsyncWebServer` это путь `AsyncProgmemResponse`: данные читаются из flash сетевыми порциями, а не копируются целиком в Arduino `String`.

Это тот же принцип, который обязателен для большого `WEB_UI_HTML`: крупный статический ресурс нельзя сначала целиком материализовать в RAM.

## Почему нет больших PNG

Для favicon браузера достаточно ICO 16/32 и SVG. PNG 180×180, 192×192 и 512×512 сейчас не добавляются, потому что они нужны в основном для полноценного installable-PWA/home-screen сценария и дают мало пользы локальной панели контроллера относительно занимаемого flash.

Если такой сценарий станет реальным требованием, растровые PWA-иконки добавляются отдельно с измерением размера firmware и новым budget-тестом, а не «на всякий случай».

## Источники и проверка

- firmware asset: `src/web_assets.h`;
- SVG для README/документации: `docs/assets/hydroesp-favicon.svg`;
- проверка: `python3 tools/check_web_assets.py`.

Тест проверяет валидность SVG, ICO header/dimensions, идентичность firmware/documentation SVG, flash-budget и наличие потоковой выдачи с HTTP cache.
