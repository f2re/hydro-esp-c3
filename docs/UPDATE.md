# Обновление HydroESP-C3

После первичной USB-прошивки штатный способ обновления — OTA в доверенной локальной сети.

## Перед обновлением

1. убедитесь, что насос выключен;
2. не отключайте питание контроллера во время записи flash;
3. сделайте резервную копию расписания;
4. используйте только прошивку для HydroESP-C3 / ESP32-C3 Super Mini;
5. не выполняйте OTA через публичную/недоверенную сеть.

Резервная копия из CLI:

```bash
python3 tools/hydroctl.py backup --output hydroesp-backup.json
```

Веб-интерфейс также имеет **Система → Резервная копия → Экспорт JSON**. Пароль Wi‑Fi в backup не экспортируется.

## Вариант 1 — обновление из веб-интерфейса

1. откройте `http://hydro.local`;
2. перейдите в **Прошивка**;
3. перетащите `firmware.bin` в область загрузки;
4. проверьте имя и размер файла;
5. подтвердите обновление;
6. дождитесь завершения записи и перезапуска.

Во время OTA прошивка принудительно останавливает насос.

## Вариант 2 — последняя опубликованная версия одной командой

### macOS / Linux

```bash
bash update.sh
```

### Windows

```powershell
.\update.ps1
```

### Универсально

```bash
python3 tools/hydroctl.py update
```

`hydroctl`:

1. получает последний GitHub Release;
2. загружает release `.bin`;
3. загружает `.sha256`;
4. проверяет SHA-256, если checksum присутствует;
5. отправляет образ на `/ota/upload`;
6. сообщает о принятии OTA устройством.

Если устройство доступно не как `hydro.local`:

```bash
python3 tools/hydroctl.py update --host http://192.168.1.50
```

## Вариант 3 — локальный файл

```bash
python3 tools/hydroctl.py update --file .pio/build/esp32c3_supermini/firmware.bin
```

Или с другим адресом:

```bash
python3 tools/hydroctl.py update \
  --host http://192.168.1.50 \
  --file hydro-esp-c3-v1.2.0.bin
```

## Сборка собственной версии

```bash
python3 tools/hydroctl.py build
```

Результат:

```text
.pio/build/esp32c3_supermini/firmware.bin
```

Чистая пересборка:

```bash
python3 tools/hydroctl.py build --clean
```

## Release-процесс проекта

Workflow `.github/workflows/release.yml` запускается по тегу `v*` и:

1. собирает прошивку из конкретного Git commit;
2. встраивает tag/version и короткий build SHA;
3. формирует versioned `.bin`;
4. формирует `hydro-esp-c3-latest.bin`;
5. создаёт SHA-256 список;
6. публикует GitHub Release с release notes.

Пример выпуска:

```bash
git tag -a v1.2.0 -m "HydroESP-C3 v1.2.0"
git push origin v1.2.0
```

Тег должен указывать на проверенный commit `main` с зелёным CI.

## Проверка после обновления

После перезапуска:

```bash
python3 tools/hydroctl.py doctor
```

Проверьте:

- версию и build SHA;
- синхронизацию NTP;
- сохранённое расписание;
- Wi‑Fi;
- короткий ручной цикл насоса.

Версия также отображается в **Обзор → Связь** и **Система → Диагностика**.

## Восстановление расписания

CLI:

```bash
python3 tools/hydroctl.py restore hydroesp-backup.json
```

Это восстанавливает только расписание. Пароли не хранятся в backup и не восстанавливаются.

В веб-интерфейсе импорт JSON создаёт **черновик** расписания. Он не записывается в NVS, пока пользователь явно не нажмёт **Сохранить**.

## Если OTA оборвалась

1. не запускайте насос до проверки контроллера;
2. дождитесь перезапуска;
3. проверьте `hydro.local` и `doctor`;
4. если контроллер не стартует, подключите USB и выполните обычную установку:

```bash
python3 tools/hydroctl.py install
```

Таблица разделов содержит две OTA app-партиции, однако автоматический health-check/rollback после неудачного запуска пока не реализован. Поэтому наличие двух слотов нельзя считать полноценным гарантированным rollback-механизмом.

## Важное ограничение безопасности

Текущий локальный OTA endpoint не имеет web-auth и криптографической проверки подписи пользовательского образа. Пока security-этап не закрыт, используйте OTA только в доверенной изолированной LAN. Подробности: [SECURITY.md](SECURITY.md).
