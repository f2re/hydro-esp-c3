# Диагностика HydroESP-C3

Начинайте с одной команды:

```bash
python3 tools/hydroctl.py doctor
```

Она показывает локальный toolchain, serial-порты, доступность контроллера, версию прошивки и состояние синхронизации времени.

## Контроллер не появляется после прошивки

1. откройте Serial monitor:

```bash
python3 tools/hydroctl.py monitor
```

2. найдите строку версии `HydroESP` и этап загрузки;
3. если домашний Wi‑Fi не настроен или недоступен, устройство должно создать `HydroESP-Setup`;
4. подключитесь к этой сети и откройте `http://192.168.4.1`.

Если точки доступа нет, повторите USB-прошивку и проверьте питание.

## `hydro.local` не открывается

mDNS поддерживается не каждой сетью/клиентом одинаково.

Проверьте:

- компьютер и ESP находятся в одной LAN/VLAN;
- client isolation на Wi‑Fi выключен;
- устройство получило IP;
- `doctor` видит устройство;
- IP можно открыть напрямую в браузере.

Пример:

```bash
python3 tools/hydroctl.py status --host http://192.168.1.50
```

## В интерфейсе «Нет связи», но Wi‑Fi есть

Веб-страница опрашивает `/api/status`. Проверьте:

```bash
curl http://hydro.local/ping
curl http://hydro.local/api/status
```

Или без `curl`:

```bash
python3 tools/hydroctl.py status
```

Если ответы периодически исчезают, проверьте RSSI, питание и перезапуски.

## Расписание не запускается

Расписание намеренно не работает без синхронизированного времени.

Проверьте в UI:

- **Обзор → Время**;
- статус синхронизации;
- следующий цикл;
- часовой пояс.

Также убедитесь, что сеть имеет доступ к NTP-серверу `pool.ntp.org`. При изолированной LAN без выхода к NTP текущая версия не имеет RTC и не может гарантировать абсолютное время после перезапуска.

## Насос не включается вручную

В веб-интерфейсе старт защищён от случайного касания: кнопку нужно удерживать примерно 0,7 секунды.

Физическая BOOT-кнопка также требует удержания для запуска. Если насос уже работает, короткое нажатие останавливает его сразу.

Проверьте:

1. GPIO реле — 4;
2. общий GND между логикой реле и ESP, если схема этого требует;
3. полярность/тип релейного модуля;
4. питание насоса отдельно от слабого 3,3 В регулятора ESP;
5. короткий тест 30 секунд.

## ESP перезагружается при старте насоса

Это признак проблем питания/ЭМС, а не проблема расписания.

Проверьте по приоритету:

1. отдельное питание насоса достаточной мощности;
2. общий GND и правильную топологию земли;
3. развязку/драйвер реле;
4. обратный диод для индуктивной DC-нагрузки там, где он требуется схемой;
5. конденсаторы по питанию ESP около платы;
6. падение напряжения осциллографом или быстрым логгером;
7. кабели и контакты;
8. помехи от двигателя/насоса.

В текущей конфигурации сохранён временный `HYDRO_DISABLE_BROWNOUT_WORKAROUND=1`. Его назначение — совместимость со старой установкой, а не нормализация плохого питания. После аппаратного исправления установите значение `0` и снова протестируйте.

## Происходит лишний полив после ручного запуска

В актуальной версии планировщик помечает минуту обработанной даже если насос занят ручным циклом. Поэтому плановый слот, совпавший с ручным поливом, не должен запускаться «догоняющим» циклом после его окончания.

Если вы видите обратное:

1. запишите точное время;
2. сохраните версию/build SHA из UI;
3. приложите Serial log;
4. приложите JSON расписания из backup;
5. создайте issue.

## Расписание исчезло или повреждено

NVS-хранилище проверяет длину и диапазоны слотов. При некорректных сохранённых данных применяется заводской fallback-профиль.

Перед изменениями делайте backup:

```bash
python3 tools/hydroctl.py backup
```

Восстановление:

```bash
python3 tools/hydroctl.py restore hydroesp-backup.json
```

## OTA выдаёт ошибку

Проверьте:

- расширение `.bin`;
- размер файла больше 10 КБ;
- стабильное питание;
- устройство доступно по сети;
- используется application firmware, собранный этим проектом;
- flash-разметка соответствует `partitions.csv`.

После ошибки используйте USB recovery:

```bash
python3 tools/hydroctl.py install --clean
```

## Как собрать диагностический пакет для issue

Укажите:

- модель платы;
- схему питания насоса и реле;
- версию/build SHA;
- браузер и устройство (desktop/mobile);
- результат `doctor`;
- последние строки Serial;
- шаги воспроизведения;
- ожидаемое и фактическое поведение.

Не публикуйте пароль Wi‑Fi, приватные SSID при необходимости замаскируйте.
